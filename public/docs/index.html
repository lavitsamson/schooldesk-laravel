Introduction

The parent portal as a JSON API for a mobile app: children, attendance, grades, report cards, invoices and notifications.

Base URL: http://localhost 
Parents sign in with the email address and password of their parent portal account and get a bearer token for one school (`POST /api/v1/auth/token`). Every request then acts for that school only.

<aside>
<strong>Conventions.</strong> Responses wrap their content in <code>data</code>. Lists are cursor-paginated (<code>?limit=</code>, 1–100, and <code>?cursor=</code> from <code>meta.next_cursor</code>). Amounts are integers in minor units (cents) of the school's currency (<code>GET /me</code>). Dates are <code>YYYY-MM-DD</code>, times ISO 8601.
Errors always look like <code>{"message": "…", "code": "not_found"}</code>, with <code>errors</code> per field for <code>validation_failed</code> (422). Records of other schools are 404; another family's records 403. 60 requests a minute per token.
</aside>

Demo: sign in as <code>parent@riverside.demo</code> with the password <code>DemoPass123!</code>.

Authenticating requests

To authenticate requests, include an Authorization header with the value "Bearer {YOUR_TOKEN}".

All authenticated endpoints are marked with a requires authentication badge in the documentation below.

Get a token from POST /api/v1/auth/token and send it as Authorization: Bearer {token}.

Authentication

Parents sign in with the email address and password of their parent portal account. Each token is for one device and one school; send it as Authorization: Bearer <token>.

Get a token

Parents at several schools choose one with school_id (the error lists their schools). Tokens expire after 90 days. Limited to 5 attempts a minute per email address.

Example request:
curl --request POST \
    "http://localhost/api/v1/auth/token" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json" \
    --data "{
    \"email\": \"parent@riverside.demo\",
    \"password\": \"DemoPass123!\",
    \"device_name\": \"Paula\'s iPhone\"
}"

const url = new URL(
    "http://localhost/api/v1/auth/token"
);

const headers = {
    "Content-Type": "application/json",
    "Accept": "application/json",
};

let body = {
    "email": "parent@riverside.demo",
    "password": "DemoPass123!",
    "device_name": "Paula's iPhone"
};

fetch(url, {
    method: "POST",
    headers,
    body: JSON.stringify(body),
}).then(response => response.json());

Example response (201):

Headers

Content-Type        

Example: application/json

Accept        

Example: application/json

Body Parameters

email   string     

The parent account's email address. Must be a valid email address. Must not be greater than 255 characters. Example: parent@riverside.demo

password   string     

The account's password. Must not be greater than 255 characters. Example: DemoPass123!

device_name   string     

A name for the device, shown to the parent later. Must not be greater than 100 characters. Example: Paula's iPhone

school_id   integer  optional    

Only for parents at several schools: the school the token is for.

Revoke the token
